# Two-Stage Cross-Encoder Reranking Engine (`ranking_agent`)

## 1. Executive Overview & Foundational Invariants

The AI Factory Two-Stage Reranking Engine enhances Knowledge Oracle queries, autonomous debates, and evidence validation by pairing fast, high-recall vector search (Stage 1) with precise cross-encoder semantic reranking (Stage 2). Standard single-stage RAG retrieves text by comparing dense embedding vectors generated by a Bi-Encoder (e.g., `bge-m3`, `text-embedding-004`). While Bi-Encoders are fast and scalable via approximate nearest neighbor (ANN) indexes, they project entire passages into static vector embeddings, losing token-level interactions, exact keyword alignment, and nuanced query-context semantics.

### Foundational Invariants
- **Recall Depth Disparity (`recall_k`)**: Stage 1 casts a wide net (Oracle: $\min(\max(k \times 4, 75, |\text{Tables}| \times 4), 150)$; Validator: $\min(\max(k \times 4, 30, |\text{Tables}| \times 4), 100)$; YAML default: $30$), ensuring relevant chunks that scored moderately in cosine distance or Reciprocal Rank Fusion (RRF) are surfaced for deep neural inspection.
- **Context Precision (`top_k`)**: Stage 2 filters the deep candidate pool down to the highest-scoring $k$ chunks (default `top_k = 5`), eliminating vector noise and preserving the LLM's active context window.
- **Two-Tier Fail-Open Safety (Graceful Degradation)**: If a remote reranker HTTP endpoint is offline, times out, or returns a non-200 status code (e.g., 400, 422, 503), the engine logs a diagnostic note to `stderr` and intentionally falls through to the in-process local cross-encoder. If local loading or scoring fails, the engine catches the exception, logs a warning, and falls back to Stage 1 vector/RRF ordering without interrupting execution.
- **Offline-First Local Execution**: In-process local models are loaded with `local_files_only=True` first, guaranteeing zero outbound network requests and suppressing unauthenticated Hugging Face Hub telemetry warnings on air-gapped systems. Cold-start downloads occur only if local cache misses occur.
- **Architecture Auto-Detection**: The engine dynamically inspects Hugging Face model metadata (`AutoConfig`) to route models to either the classic `sentence_transformers.CrossEncoder` pipeline or native `AutoModel.rerank()` listwise pipelines (e.g., for `jinaai/jina-reranker-v3.5`), preventing corrupted classification head initialization.
- **Strict Read-Only Context Isolation**: Reranking operates strictly on retrieved in-memory chunk dicts. It never mutates LanceDB tables, edits files, or persists temporary state to disk.

## 3. Technical Mechanics & Deep-Dive Logic

### 3.1 Mathematical Formulations

#### 1. Stage 1: Reciprocal Rank Fusion (RRF) Multi-Table Merge
When retrieving across multiple LanceDB tables (e.g., separating code tables from documentation tables or per-document literature tables), each table returns an independent rank list ordered by cosine distance. RRF merges these lists into a single unified candidate ranking:
$$\text{RRF\_Score}(d \in D) = \sum_{t \in \text{Tables}} \frac{1}{c + \text{rank}_t(d)}$$
where $c = 60$ is the ranking constant (Cormack et al., 2009).

To guarantee strict determinism across distributed filesystems and operating systems, ties in $\text{RRF\_Score}$ are broken using a deterministic secondary key:
$$\text{SortKey}(d) = \left( -\text{RRF\_Score}(d),\, \text{source\_file}(d),\, \text{text}(d)[:64] \right)$$

#### 2. Stage 2: Classic Pairwise Cross-Encoder Scoring
Unlike Bi-Encoders which compute cosine similarity over independent vectors $\cos(E(Q), E(D))$, Cross-Encoders pass the concatenated sequence through full bi-directional self-attention:
$$X_i = [\text{CLS}] \circ Q \circ [\text{SEP}] \circ D_i \circ [\text{SEP}]$$
The sequence representation is evaluated via a classification head over the $[\text{CLS}]$ token:
$$s_i = \mathbf{w}^T \text{Transformer}(X_i)_{[\text{CLS}]} + b$$
For multi-class or binary logit outputs $[z_{\text{neg}}, z_{\text{pos}}]$, the positive class logit is extracted:
$$s_i = z_{\text{pos}} \quad \text{or} \quad \sigma(z_{\text{pos}}) = \frac{1}{1 + e^{-z_{\text{pos}}}}$$

#### 3. Stage 2: Native Listwise "Last but Not Late" (LBNL) Ranking (Jina v3.x)
Models such as `jinaai/jina-reranker-v3.5` utilize a custom `JinaForRanking` architecture with an asymmetric MLP projection layer ($1024 \to 512 \to 512$) and joint cosine interaction:
$$s_i = \cos\left( \text{MLP}_{\text{proj}}(H_Q),\, \text{MLP}_{\text{proj}}(H_{D_i}) \right)$$
where $H_Q$ and $H_{D_i}$ represent contextualized embeddings evaluated jointly across the candidate batch, optimizing listwise permutations rather than independent binary classification.

#### 4. Downstream Validator Region Similarity Conversion
In `validator.py`, the region similarity metric $\text{sim} \in [0, 1]$ used for claim grounding is derived directly from the top reranked chunk:
$$\text{sim} = \begin{cases} s_0, & \text{if } s_0 = \text{rows}[0].\text{get}('_relevance\_score') \text{ exists} \\ 1.0 - d_{\text{cosine}}(\text{rows}[0]), & \text{otherwise} \end{cases}$$

### 3.2 Algorithmic Execution Flow (`_rerank_chunks`)

The reranking engine is implemented in `oracle_agent.py` and consumed by both `oracle_agent.py` and `validator.py`.

```python
def _rerank_chunks(query: str, candidates: list[dict], top_n: int = 5) -> list[dict]:
```

1. **Bypass Checks**:
   - If $\text{len}(candidates) \le 1$, return $candidates[:top\_n]$.
   - If $ORACLE\_NO\_RERANK == "1"$, return $candidates[:top\_n]$.
   - If $ORACLE\_RANKING\_MODEL$ is empty or unset, return $candidates[:top\_n]$.

2. **Remote HTTP Endpoint Path**:
   - Triggered when `ORACLE_RANKING_API_BASE` is non-empty.
   - Normalizes endpoint URL: strips trailing slashes and trims `/v1` suffix to derive `base_no_v1`.
   - Constructs dual-key JSON payload to support Text Embeddings Inference (TEI), Jina, Cohere, and LiteLLM simultaneously:
     ```json
     {
       "model": "jinaai/jina-reranker-v3.5",
       "query": "query string",
       "documents": ["chunk 1", "chunk 2"],
       "texts": ["chunk 1", "chunk 2"],
       "top_n": 30
     }
     ```
     > **Compatibility Note:** Sending both the `"documents"` and `"texts"` keys simultaneously in the JSON payload guarantees seamless compatibility across Jina/Cohere APIs (which expect `"documents"`) and TEI APIs (which expect `"texts"`), eliminating the need for backend-specific configuration flags.
   - Dispatches `POST {base_no_v1}/v1/rerank` with `timeout=10` and `Authorization: Bearer sk-dummy`.
   - If endpoint returns HTTP `404 Not Found`, automatically retries `POST {base_no_v1}/rerank`.
   - If HTTP status is `200 OK`:
     - Parses `results` (or `data`) list.
     - Maps `score = item.get("relevance_score", item.get("score"))` back to candidate at `idx = item.get("index")`.
     - Assigns `candidates[idx]["_relevance_score"] = float(score)`.
     - Sorts scored candidates descending, appends unscored candidates at the bottom, and returns the top `top_n`.
   - If HTTP status is non-200 or connection raises an exception:
     - Emits diagnostic notification to `stderr`: `[rerank] note: remote reranker unavailable... falling through to local in-process reranker.`
     - **Control intentionally falls through to the In-Process Local Path.**

3. **In-Process Local Model Path (`_load_local_reranker`)**:
   - Reuses cached model singleton `_RERANKER_LOCAL_INSTANCE`.
   - **Architecture Sniffing (`_is_native_listwise`)**:
     - Inspects `transformers.AutoConfig.from_pretrained(model, trust_remote_code=True, local_files_only=True/False)`.
     - Checks if `architectures` or `auto_map` contains the substring `"Ranking"` (e.g., `JinaForRanking`).
   - **Backend A: Native Listwise Rerankers (`AutoModel`)**:
     - Loaded via `transformers.AutoModel.from_pretrained(model, dtype="auto", trust_remote_code=True, local_files_only=True)`.
     - On cache miss, re-attempts with `local_files_only=False` to download weights once.
     - Calls `instance.rerank(query, docs)`.
     - Maps returned relevance scores to `candidates[idx]["_relevance_score"]`.
   - **Backend B: Classic Pairwise Cross-Encoders (`CrossEncoder`)**:
     - Loaded via `sentence_transformers.CrossEncoder(model, trust_remote_code=True, local_files_only=True/False)`.
     - Formats query-document pairs: `pairs = [[query, c.get("text", "")] for c in candidates]`.
     - Computes predictions: `scores = instance.predict(pairs)`.
     - Extracts scores safely via `_extract_score`:
       - Scalar: `float(val.item())` or `float(val)`.
       - Array/List: `float(val[-1])` (extracts positive class from `[neg, pos]` binary logits).
   - **Local Exception Handling**:
     - If local scoring fails, catches `Exception`, logs `[rerank] warning: local rerank failed ({e}); falling back to vector order.` to `stderr`, and returns `candidates[:top_n]`.

4. **Sorting and Truncation**:
   - Candidates with `_relevance_score` are sorted in descending order.
   - Any unscored candidates are appended at the bottom.
   - Truncates and returns `candidates[:top_n]`.

> **CRITICAL ARCHITECTURAL INVARIANT**:
> Do **NOT** load `jina-reranker-v3.x` through `sentence_transformers.CrossEncoder`. `CrossEncoder` routes non-`ForCausalLM` architectures through `AutoModelForSequenceClassification`. For `JinaForRanking`, this **silently discards the projector head and randomly initializes `score.weight`** (`score.weight | MISSING … newly initialized`), yielding corrupted, non-deterministic scores.

### 3.4 Academic Foundations & Literature References

1. **Reciprocal Rank Fusion (RRF)**:
   - **Citation**: Cormack, G. V., Clarke, C. L., & Buettcher, S. (2009). *Reciprocal rank fusion outperforms Condorcet and individual rank learning methods.* Proceedings of the 32nd International ACM SIGIR Conference on Research and Development in Information Retrieval (SIGIR '09), 758–759. DOI: [10.1145/1571941.1572114](https://doi.org/10.1145/1571941.1572114)
   - **Significance**: Proves that harmonic rank-based fusion out-performs score-based normalization across heterogeneous vector index spaces.

2. **Cross-Encoder Neural Reranking**:
   - **Citation**: Nogueira, R., & Cho, K. (2019). *Passage Re-ranking with BERT.* arXiv preprint [arXiv:1901.04085](https://arxiv.org/abs/1901.04085).
   - **Significance**: Establishes that full cross-attention over concatenated $(Q, D)$ pairs captures subtle token interactions lost during dual-encoder embedding projection.

3. **Listwise Neural Ranking with Projector Heads**:
   - **Citation**: Günther, M., et al. (2024). *Jina Reranker: A Compact and Multilingual Model for Neural Information Retrieval.* Jina AI Technical Report.
   - **Significance**: Introduces "Last but Not Late" (LBNL) scoring, utilizing joint projection layers across candidate lists for permutation-aware reranking.

## 6. Operational Edge Cases, Failure Modes & Telemetry

| Failure Mode | Observable Signature / Stderr Trace | Root Mechanism | Resolution & Recovery Procedure |
| :--- | :--- | :--- | :--- |
| **Remote Server Non-200 / Timeout** | `[rerank] note: remote reranker unavailable... falling through to local in-process reranker.` | Network interruption, container crash, or inference timeout (>10s). | The engine automatically falls through to the local in-process reranker. If local weights exist, scoring succeeds seamlessly. |
| **Endpoint 404 Routing Mismatch** | First attempt to `/v1/rerank` fails with 404, followed by clean 200 response. | TEI and custom proxies expose `/rerank` instead of `/v1/rerank`. | Automated recovery: `_rerank_chunks` automatically retries `{base_no_v1}/rerank`. Zero user action required. |
| **Jina v3 Architecture Head Corruption** | Warning: `Some weights of JinaForRanking were not initialized... score.weight | MISSING`. Non-deterministic scores. | Model was forced through `sentence_transformers.CrossEncoder`, discarding the MLP projector head. | Ensure `_load_local_reranker` is used; it sniffs `AutoConfig` and loads `JinaForRanking` via `transformers.AutoModel` with `trust_remote_code=True`. |
| **Air-Gapped Cache Miss on First Boot** | `OSError: We couldn't find the model at... (local_files_only=True)`. | System is offline and model weights were not pre-cached in Hugging Face Hub cache. | Pre-seed weights prior to air-gapping: run `huggingface-cli download <model_name>` or populate `$HF_HOME/hub`. |
| **Multi-Dimensional Logit Output** | `_extract_score` receives 2D numpy array `[[-0.42, 2.15]]`. | Binary cross-encoder outputs un-softmaxed logits for `[negative, positive]` classes. | Handled automatically: `_extract_score()` inspects array length and extracts `val[-1]` (positive class). |
| **Near-Zero or Inverted Scores on `llama-server`** | Scores like `1.24e-28`, with completely irrelevant documents ranking at the top. | Missing `--embedding` and `--pooling rank` flags on `llama-server`, causing unscaled vocabulary-wide softmax. | Launch `llama-server` with `--reranking --embedding --pooling rank`. Verify GGUF was converted with `cls.output.weight`. |
| **Complete Engine Failure (Zero Scored Chunks)** | `[rerank] warning: local rerank failed... falling back to vector order.` | In-process out-of-memory (OOM) or missing PyTorch C++ bindings. | Engine catches exception and safely returns `candidates[:top_n]` in Stage 1 vector/RRF order without terminating pipeline. |
